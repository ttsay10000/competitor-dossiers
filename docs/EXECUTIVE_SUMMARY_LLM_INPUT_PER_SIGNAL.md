# What Is Sent to the Executive Summary LLM, Per Signal

The executive summary is generated by `generate_executive_summary(context)` in `app/executive_summary.py`. The text the LLM sees is built by `_build_context_text(context)` from the same `context` dict produced by `build_dossier_context()` in `app/routes/dossier.py`.

**Rule:** Only the following data is sent. When a **refresh exists** (new snapshot after baseline), we send **changes only**. When **only baseline exists** (no refresh), we send **baseline state** so the summary can describe current footprint/counts.

- **Top news** — Latest news from the past 2–3 weeks only (`top_news`; no raw `press_90d`).
- **Asset** — Changes in property numbers vs baseline per state (additions/removals, new states), or baseline footprint if no refresh.
- **Jobs** — Changes in job numbers since baseline, or baseline open-role count if no refresh.
- **Website changes** — Any changes since last refresh (events: `narrative.homepage_updated`, `narrative.coming_soon`).
- **Social / Google reviews** — New updates since baseline: social via `narrative.social_signal` events; reviews as significant sentiment (current snapshot when no review diff).

Events are not capped; all `events_this_week` are sent. Other caps (news, delta rows, review sample) are noted below.

---

## 1. Talent

**Context keys used:** `has_talent_refresh_since_baseline`, `jobs_added_since_baseline`, `jobs_removed_since_baseline`, `talent_jobs`.

**When a refresh exists:**  
`Job changes since baseline: <N> new roles posted, <M> removed. Current open roles: <total>.`

**When only baseline:**  
`Open roles (baseline; no refresh yet): <total>. No job count changes.`

**Plus:** Talent events (e.g. `talent.senior_hire_or_role_posted`, `talent.hiring_surge`) appear in the **Signals since last refresh** block as `title [talent.<type>]`.

---

## 2. Asset (properties / footprint)

**Context keys used:** `has_asset_refresh_since_baseline`, `asset_added_since_baseline`, `asset_removed_since_baseline`, `asset_delta_by_city`, `total_properties`, `properties_by_location`.

**When a refresh exists:**  
`Property changes since baseline — New: <N> in <M> areas: <loc>: <added>; ...`  
`Property changes since baseline — Removed: <N> in <M> areas: <loc>: <removed>; ...`  
(Delta rows capped at `MAX_DELTA_BY_CITY_ROWS` = 15.)

**When only baseline:**  
`Property footprint (baseline; no refresh yet): <N> properties — <loc>: <count>; ...`

**Plus:** Asset events (e.g. `asset.new_market`, `asset.market_exit`) appear in the Signals block as `title [asset.<type>]`.

---

## 3. Press / news (top news only)

**Context key used:** `top_news` only. **No** `press_90d` fallback for the executive summary.

**What the LLM sees:**  
Items are filtered to the past **21 days** (`TOP_NEWS_DAYS`). One block:  
`Top news (last 2-3 weeks; derive bullets from these): (<date>) <title> [<group_title>] | ...`  
Capped at `MAX_NEWS_FOR_SUMMARY` (15). `top_news` is produced by `summarize_top_news_llm(..., days=21)` in `build_dossier_context`.

---

## 4. Digital footprint (website / homepage changes)

**No dedicated context block.** This signal reaches the LLM **only via events**:

- Event types: `narrative.homepage_updated`, `narrative.coming_soon`.
- Sent in the **Signals since last refresh** block as: `title [website/digital footprint]`.

These represent **changes since last refresh** (homepage diff, coming-soon detection).

---

## 5. Social media (LinkedIn / Twitter, etc.)

**No dedicated context block.** Social reaches the LLM **only via events**:

- Event type: `narrative.social_signal` (executive-relevant new posts).
- Sent as: `title [social]` in the Signals block.

---

## 6. Reviews (Google reviews for properties)

**Context key used:** `reviews_minimal` — list of `{ display_name, line (sentiment_summary), trend }` per property.

**What the LLM sees:**  
Only when there are **major or significant changes**:  
`Review sentiment (significant changes / current snapshot): <display_name>: <line> (trend: <trend>) | ...`  
Significant = declining/negative trend or negative markers (complaint, poor, issue). Up to `MAX_REVIEW_PROPERTIES_FOR_SUMMARY` (10).

---

## 7. Events — “Signals since last refresh” block

**Context key:** `events_this_week` (events in the last 7 days).

**What the LLM sees:**  
`Signals since last refresh (website changes, social, talent/asset events): <title1> [website/digital footprint]; <title2> [social]; <title3> [talent.*]; ...`  
- `narrative.homepage_updated` / `narrative.coming_soon` → `[website/digital footprint]`  
- `narrative.social_signal` → `[social]`  
- Other types sent as `[<event_type>]`. All events included (no cap).

---

## 8. Baseline (shared)

**Context keys:** `comparison_baseline_date`, `has_asset_refresh_since_baseline`, `has_talent_refresh_since_baseline`.

**When at least one channel has a refresh:**  
`Comparison baseline date: <date>. Summarize only CHANGES since baseline (property/job deltas, new events). Do not restate baseline state.`

**When only baseline (no refresh):**  
`Comparison baseline date: <date>. Only baseline data available (no refresh since). Summarize current state where applicable.`

---

## Summary table: what is sent per signal

| Signal            | Context keys                                      | What the LLM actually sees                                                                 |
|-------------------|---------------------------------------------------|---------------------------------------------------------------------------------------------|
| Talent            | has_talent_refresh_since_baseline, jobs_*_since_baseline, talent_jobs | Changes since baseline (or baseline count) + talent events in Signals block                |
| Asset             | has_asset_refresh_since_baseline, asset_*_since_baseline, asset_delta_by_city, total_properties, properties_by_location | Changes since baseline (or baseline footprint) + asset events in Signals block             |
| Press             | top_news only (no press_90d)                      | “Top news (last 2-3 weeks)”: up to 15 items, filtered to 21 days                           |
| Digital footprint | (events only)                                    | Signals block: `title [website/digital footprint]`                                         |
| Social            | (events only)                                    | Signals block: `title [social]`                                                            |
| Reviews           | reviews_minimal                                  | Only when significant: “Review sentiment (significant changes / current snapshot)” (up to 10) |
| Other events      | events_this_week                                 | Signals block: `title [<event_type>]`                                                      |

Events are sent without a cap; the full `events_this_week` list is included.
