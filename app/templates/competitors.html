Global reset — only use if sure

The seed file (seed_data.json) is the canonical list of competitors and sources in your repo. It’s used on deploy and when you want to sync between the database and the file.

  • Run seed — File → DB. Use when the seed file was updated (e.g. you pulled from git or edited seed_data.json by hand) and you want to load that into the database. Loads seed_data.json into the DB.
  • Export seed — DB → file. Use when you’ve added or edited competitors in the UI and want to persist them to the seed file. Writes the current DB to seed_data.json. Do this whenever you add competitors via the UI so the file stays in sync. You do not need to click Run seed after this.
  • Force refresh & reset baseline — Runs seed (file → DB) first, then deletes all snapshots and events, runs all collectors for all channels, then sets each competitor’s baseline to the time the run completed (so “Baseline set” shows that date). Use when the seed file is up to date (e.g. after Export seed if you added in UI), after editing the seed file, or when changing press/LLM logic. Does not run Export seed; use Export seed separately to save UI changes back to the file.
